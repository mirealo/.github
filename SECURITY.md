# Security policy

Security is a core requirement for every Mirealo project.

## Reporting a vulnerability

Do not open a public issue, discussion, or pull request for a suspected
vulnerability.

Use the affected repository's **Report a vulnerability** option under its
Security tab. This creates a private vulnerability report visible only to the
repository's security maintainers. If private reporting is not available,
contact the organization through an established private business channel and
include only enough information to establish a secure reporting path.

Include, when available:

- the affected repository, component, and version;
- the impact and realistic attack scenario;
- minimal reproduction steps or a proof of concept;
- known mitigations or workarounds;
- whether the issue has been disclosed elsewhere.

We will acknowledge a valid private report, assess severity, coordinate a fix,
and communicate disclosure timing through the private report. Please allow a
reasonable remediation period before any public disclosure.

## Scope

Only supported versions and the default branch are normally eligible for
security fixes. Individual repositories may publish a more specific support
window that takes precedence over this policy.

Testing must not degrade services, access data belonging to others, use social
engineering, or cause denial of service.
